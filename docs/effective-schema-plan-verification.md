## 3. Canonical version and shape

`formatVersion`, `policyVersion` and `namingVersion` are all 1. The plan has

## 4. Stable IDs

`stableId()` encodes each scoped tuple component with `encodeURIComponent`.
Entities use their spelling; declared fields use entity/name; implicit fields
have a distinct origin prefix; relationship fields include receiver/relation
scope/name. Relation IDs use source/name/target/cardinality to distinguish
representable direct-IR relationships; junction and junction-field IDs use
endpoint/name scopes. Lines, traversal ordinals, object identity and generated
content hashes never determine IDs. Tests move locations, insert unrelated
declarations and change defaults without changing the corresponding identities.

## 11. Ordering and views

## 12. Relationship normalization

ONE_TO_MANY places the source-key FK on the target; MANY_TO_ONE places the
target-key FK on the source. Both are nullable/nonunique with SET NULL.
ONE_TO_ONE places a nullable UNIQUE source-key FK on the target with CASCADE.
MANY_TO_MANY stores two nonnullable FKs, ordered composite identity and
CASCADE references in junction storage. Synthetic fields inherit logical type
only. `typeSourceFieldId` preserves referenced physical STRING width without
inheriting default, bounds, generation, PRIMARY_KEY or REQUIRED policy. All four
cardinalities and INT/UUID, UUID/STRING, STRING/INT, UUID/UUID pairs are tested.
